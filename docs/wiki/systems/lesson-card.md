# レッスン・試験のカードロジック

[プロデュース](produce.md)のレッスン・試験で使うスキルカードの挙動を、実装できる粒度で定義する。

参考作品のシステム構造を調査して決めた。名称は Uta の仮称で、カードは記号(F01 など)で表す([ADR 0001](../decisions/0001-ip-policy.md))。表示名は未決。

## 凡例

- **[確認]** 参考作品の攻略情報で裏取りした構造
- **[決定]** Uta で決めたこと
- **[Uta案]** 実装方針の提案(まだ決定ではない)

数値: カード効果の数値は、参考作品の値を**仮の値**として使う(バランス調整で差し替える前提)。

## 1. スコープ

| 含める | 含めない |
|---|---|
| プラン: 感性 / 理論 / 共通 | 第3のプラン(指針を切り替える型)一式 |
| レアリティ: N / R / SR / SSR | 最上位レアのカード |
| アクティブ / メンタル / 不調カード(1種のみ) | カードのカスタマイズ |
| 強化(+)、レッスン中強化 | 再演、使用準備 |
| 発動予約、持続効果 | レッスンのギミック(応援・トラブル) |
| | 山札操作系の特殊効果 |

実装範囲の決定 [決定]:

| 項目 | 方針 |
|---|---|
| 第3のプラン | 実装しない |
| 育成アイテム・ドリンク | 実装する(フェーズ5)。カードと同じ効果エンジン(7章、10章)に乗せる |
| 低下状態(デバフ) | 採用したカード・アイテムが使うものだけ実装する |
| レッスンのギミック | 実装しない |
| 特殊な効果(7.6) | その効果を持つカードを採用するときに実装する |
| カードの枚数 | 各フェーズ10〜20枚程度で動作確認。全カードを揃えるかはフェーズ4の完了時に判断する [仮] |

## 2. 用語

| 用語 | 意味 |
|---|---|
| 山札 / 手札 / 捨札 / 除外 | カードの置き場(4章) |
| 消費 | 元気→体力の順に払うコスト。補正の影響を受ける |
| 体力消費 | 元気を無視して体力から直接払うコスト。補正の影響を受けない |
| 使用条件 | 満たさないとカードを使えない条件 |
| 効果内条件 | 効果の一部だけを条件付きで発動する条件 |
| 発動予約 | 「次のターン、〜」「Nターン後、〜」形式の遅延効果 |
| 持続効果 | 「以降、〜」「以降のNターンの間、〜」形式の常駐トリガー |
| 審査ターン | 試験で、そのターンに加点対象となるパラメータ |

ステータス名(好調・集中・好印象・やる気・元気など)は仮称。公開前に Uta 独自の名称に置き換える([glossary](../glossary.md))。

## 3. カード定義(マスタデータ)

### 3.1 フィールド

| フィールド | 型 | 内容 |
|---|---|---|
| id | string | 一意ID |
| name | string | 表示名(未決) |
| plan | enum | sense(感性) / logic(理論) / free(共通) |
| type | enum | active / mental / trouble |
| rarity | enum | N / R / SR / SSR |
| unlockLv | int | 出現に必要なプレイヤーLv |
| onceInLesson | bool | レッスン中1回。使うと除外へ |
| unique | bool | 重複不可。デッキに同じカードを2枚持てない |
| startInHand | bool | レッスン開始時に手札に入る |
| base | CardFace | 通常版の性能 |
| enhanced | CardFace | 強化版(+)の性能 |

`CardFace` の中身:

| フィールド | 内容 |
|---|---|
| costs | コストの配列(5章)。複数持てる |
| useConditions | 使用条件の配列(6章)。すべて満たすと使用可 |
| effects | 効果の配列(7章)。**記載順に上から処理** [確認] |

強化で変わるのは数値だけでなく、コスト種別・効果の追加・条件の変化もある。そのため通常版と強化版は差分ではなく丸ごと別定義で持つ。[Uta案]

### 3.2 表現例(YAML)

```yaml
- id: sense_s10
  plan: sense
  type: active
  rarity: R
  unlockLv: 13
  onceInLesson: true
  base:
    costs: [{ kind: consume, value: 4 }]
    effects:
      - { op: param, value: 17, focusScale: 1.5 }
  enhanced:
    costs: [{ kind: consume, value: 4 }]
    effects:
      - { op: param, value: 23, focusScale: 2.0 }

- id: logic_l13
  plan: logic
  type: active
  rarity: SR
  onceInLesson: true
  base:
    costs: [{ kind: hpDirect, value: 3 }]
    effects:
      - { op: paramByRatio, source: genki, percent: 130 }  # 減少前の元気を参照
      - { op: scaleResource, target: genki, percent: 50 }  # 元気を半分に
  enhanced:
    costs: [{ kind: hpDirect, value: 3 }]
    effects:
      - { op: paramByRatio, source: genki, percent: 180 }
      - { op: scaleResource, target: genki, percent: 50 }
```

L13 のように「参照してから変化させる」カードは、効果の記載順がそのまま意味になる。

## 4. ゾーンと移動

| ゾーン | 内容 |
|---|---|
| 山札 | レッスン開始時にデッキ全体をシャッフルして置く |
| 手札 | ターン開始時に山札から3枚引く [確認] |
| 捨札 | 使用済みカード、ターン終了時に残った手札 |
| 除外 | レッスン中1回のカードの使用後。レッスン中は戻らない [確認] |

移動ルール:

- 通常カードは使用後に捨札へ、レッスン中1回のカードは除外へ。[確認]
- ターン終了時、使わなかった手札は捨札へ。[確認]
- 山札が0枚になった瞬間に、捨札をすべてシャッフルして新しい山札にする。[確認]
  - ターン開始時のドローでも、効果によるドローでも同じ。
  - 山札を0枚にしたドローで手札に来たカードは、この再シャッフルに含まれない。
  - 1回のドローの途中で0枚になった場合は、再シャッフル後の山札から残りを引く。[決定]
  - 山札も捨札も空なら、引ける分だけ引く。[決定]
  - 手札が空、または使えるカードが無い場合は、スキップしかできない。[確認]
- 「レッスン開始時手札に入る」カードは、1ターン目に優先して手札に入れる。[決定]
  - 3枚未満なら、残りを山札から引いて3枚にする
  - 3枚以上なら、すべて入れる。ただし5枚まで
  - 上限を超えた分は山札にシャッフルして混ぜる

### 4.1 レッスンルールのマスタ [決定]

| 項目 | 値 |
|---|---|
| 毎ターンのドロー枚数 | 3 |
| 1ターン目の最低手札枚数 | 3 |
| 1ターン目の開始時手札カードの上限 | 5 |
| 1ターンの基本スキルカード使用数 | 1 |
| スキップ時の体力回復 | 2 |

### 4.2 レッスン・試験の開始と終了 [確認]

- 体力はプロデュース全体で持ち越す。元気と強化状態はレッスンごとにリセットする。
- 終了条件:
  - レッスン: 規定ターン数の経過、またはパーフェクト目標への到達
  - 試験: 規定ターン数の経過。中間試験のみ、規定スコアへの到達でも終了
- ターン数・目標値は [produce.md](produce.md) のマスタから渡す。
- パーフェクト目標を超えた分は切り捨て、パーフェクト目標の値で止める。[決定]

## 5. コスト

| kind | 表記例 | 払い方 | 補正の影響 |
|---|---|---|---|
| consume | 消費4 | 元気から先に払い、足りない分を体力から | 受ける(9.1) |
| hpDirect | 体力消費3 | 元気を無視して体力から直接 | 受けない |
| goodConditionTurns | 好調消費2ターン | 好調のターン数を減らす | なし |
| focus | 集中消費3 | 集中を減らす | なし |
| impression | 好印象消費2 | 好印象を減らす | なし |
| motivation | やる気消費3 | やる気を減らす | なし |
| excellentTurns | 絶好調消費1 | 絶好調のターン数を減らす | なし |

- 体力消費は、消費体力の追加・削減・増加・減少もすべて無視する。[確認]
- 使えるかどうかの判定 [確認]:
  - consume: 元気+体力 ≥ 最終消費量(9.1)
  - hpDirect: 体力 ≥ コスト
  - ステータスを払うコスト: その値(ターン数) ≥ コスト
  - コスト0のカードは体力0でも使える。[決定]
- コストは使用条件とは別扱い。[確認]

## 6. 条件

### 6.1 条件の種類

| 条件 | 例 |
|---|---|
| 好調状態である / 好調がNターン以上 | S11 / S04 |
| 絶好調状態である | |
| 集中がN以上 | S05 |
| 好印象がN以上 | L02 |
| やる気がN以上 | |
| 元気がN以上 / 元気が0 | |
| 体力がN%以上 | F05 |
| Nターン目以降 | |
| レッスンのクリア目標のN%以下 | |

条件は `{ subject, comparator, value }` の汎用形で表す。[Uta案]

### 6.2 判定タイミング [確認]

- 効果内条件の判定は、コストを払う**前**に行う。
- 同じタイミングで発動する複数の効果は、条件判定をまとめて先に済ませ、その後に効果を処理する。

## 7. 効果プリミティブ [Uta案]

### 7.1 パラメータ系

| op | 効果文の例 | パラメータ |
|---|---|---|
| param | パラメータ+17 / パラメータ+4(2回) | value, hits(既定1), focusScale(既定1), goodScale(既定1) |
| paramByRatio | 好印象の150%分パラメータ上昇 | source(impression / genki / motivation), percent |
| paramBonus | パラメータ上昇量増加30%(1ターン) | percent, turns |

- `hits` は連撃。集中は1回ごとに加算される。[確認]
- `focusScale` は「集中効果をN倍適用」、`goodScale` は「好調効果をN倍適用」。[確認]
- マスタに移すときは、小数を整数（パーセント）にする（`focusScale: 1.5` → `150`）。効果は `Op`・`Value`・`Arg1`〜`Arg3` と参照列で表す（[masterdata-pipeline.md](../architecture/masterdata-pipeline.md) 3章、[ADR 0007](../decisions/0007-masterdata-with-addons.md)）

### 7.2 リソース系

| op | 効果文の例 |
|---|---|
| addGenki | 元気+4(やる気の影響を受ける) |
| addFixedGenki | 固定元気+2(強化・低下状態の影響を受けない) |
| recoverHp | 体力回復3 |
| scaleResource | 元気を半分にする。端数は切り捨て [決定] |
| setResource | 元気を0にする |

### 7.3 ステータス付与系

| op | 効果文の例 |
|---|---|
| addTurns | 好調2ターン / 絶好調3ターン / 消費体力減少2ターン / 元気増加無効2ターン |
| addStack | 集中+2 / 好印象+3 / やる気+2 / 消費体力削減1 / 低下状態無効1回 |
| addPercent | 好印象強化+10% / 集中強化20%(3ターン) |

### 7.4 カード操作系

| op | 効果文の例 |
|---|---|
| draw | スキルカードを引く / 2枚引く |
| addUses | スキルカード使用数追加+1 |
| replaceHand | 手札をすべて入れ替える |
| enhanceHand | 手札をすべてレッスン中強化 |
| createCard | 不調カードを山札のランダムな位置に生成 |

### 7.5 時間差・常駐系

| op | 効果文の例 |
|---|---|
| schedule | 次のターン、パラメータ+32 / 2ターン後、スキルカードを引く |
| persistent | 以降、アクティブスキルカード使用時、集中+1 / 以降の3ターンの間、ターン開始時、パラメータ+5 |

`schedule` は `{ delayTurns, effects[] }`、`persistent` は `{ trigger, condition?, effects[], duration? }`。`duration` はターン制限と回数制限の2種。

### 7.6 後回しにするプリミティブ(そのカードを採用するときに実装)

| op | 内容 | 理由 |
|---|---|---|
| repeatNext | 次に使うカードの効果をもう1回発動 | 再発動時にトリガーを再誘発しない等の細則が多い |
| addLessonTurn | レッスン・試験のターンを1追加 | 試験の審査ターン決定ルールと絡む |
| deckManipulate | 特定のカードを山札の一番上へ | 使用頻度が低い |

## 8. ステータス

| ステータス | 単位 | 効果 | 減り方 |
|---|---|---|---|
| 好調 | ターン | パラメータ上昇量+50% | ターン経過で1減 |
| 絶好調 | ターン | 好調の倍率に「好調ターン数×10%」を加算。好調が0なら効果なし | ターン経過で1減 |
| 集中 | 値 | パラメータ上昇量+集中値 | 減らない(コストで消費) |
| 集中強化 | % | 集中の効果を(1+N%)倍 | 付与時の指定 |
| 好印象 | 値 | ターン終了時、好印象と同じだけパラメータ上昇 | ターン開始時に1減 |
| 好印象強化 | % | 好印象による上昇を増加 | 付与時の指定 |
| やる気 | 値 | 元気の増加量+やる気値 | 減らない(コストで消費) |
| 元気 | 値 | consume コストを体力より先に肩代わり | 消費で減る |
| 消費体力減少 | ターン | consume の消費量を50%に | ターン経過で1減 |
| 消費体力増加 | ターン | consume の消費量を2倍に | ターン経過で1減 |
| 消費体力削減 | 値 | consume の消費量からN引く | 減らない |
| 元気増加無効 | ターン | 元気が増えない | ターン経過で1減 |
| 低下状態無効 | 回数 | 低下状態の付与を1回打ち消す | 打ち消すたび1減 |
| パラメータ上昇量増加 | %・ターン | パラメータ上昇量を(1+N%)倍 | ターン経過 |
| スキルカード使用数追加 | 回数 | このターンにもう1枚使える | ターン終了で消える |

値の範囲 [決定]:

- 元気・好印象・やる気・集中・ターン数は0未満にならない。
- 体力は0〜最大体力。体力回復は最大体力で止まる。
- 最終消費量(9.1)は0未満にならない。

## 9. 計算式

### 9.1 最終体力消費量(consume) [確認]

```
最終消費量 = ceil( カードの消費量 × 消費倍率 + 消費体力追加 − 消費体力削減 )

消費倍率:
  減少あり・増加なし → 0.5
  減少なし・増加あり → 2
  両方あり / 両方なし → 1
```

### 9.2 パラメータ上昇値 [確認]

```
カード値 = スキルカードのパラメータ + 集中 × (1 + 集中強化) × focusScale

好調倍率:
  好調なし              → 1
  好調あり・絶好調なし  → 1 + 0.5 × goodScale
  好調あり・絶好調あり  → 1 + (0.5 + 0.1 × 好調ターン数) × goodScale

最終パラメータ上昇値 = ceil( カード値 × 好調倍率 × (1 + 上昇量増加の総和) × (1 + 上昇量減少の総和) )
```

- 連撃は1回ごとに計算して加算する。
- paramByRatio の「スキルカードのパラメータ」は `ceil(参照値 × 倍率)`。
- 丸めは式の最後に1回だけ行う。
- 集中強化の式は仮実装。フェーズ4以降に検証する。[決定(仮)] 初期カードセットには集中強化を持つカードを入れない。

### 9.3 元気の増加量

```
元気増加量 = 効果の値 + やる気
```

- 元気増加無効中は増えない。固定元気も増えない。[決定]
- 固定元気はやる気の影響を受けない。[確認]

### 9.4 好印象によるパラメータ上昇

```
上昇値 = ceil( 好印象 × (1 + 好印象強化) × (1 + 上昇量増加の総和) )
```

- 好調倍率は乗せない。[決定]

### 9.5 試験スコア

```
スコア上昇値 = ceil( 最終パラメータ上昇値 × スコアボーナス / 100 )
```

- 切り上げは2段階(パラメータ上昇値で1回、スコアで1回)。[確認]
- スコアボーナスの式は [produce.md](produce.md) 3.3(Uta独自)。[決定]

### 9.6 数値型 [Uta案]

- `float` / `double` を使わない。`decimal` か、整数の固定小数点(%を整数で持つ)で計算する。
- 理由: クライアント(IL2CPP)とサーバー(.NET 10)で同じ結果を保証するため。`ceil` の境界で1ずれるとサーバー検証が成立しない。

## 10. ターン処理順 [確認]

```
[レッスン開始]
  L1. 「レッスン開始時」効果の条件判定 → 処理
  L2. 山札をシャッフル、開始時手札カードを配置

[ターン開始]
  T1. 発動予約の残りターンを1減らす
  T2. 好印象を1減らす(ターン開始時の他の効果より前)
  T3. 「ターン開始時」効果
  T4. 山札から3枚引く(1ターン目は4章のルール)
  T5. 「ターン開始後」効果
  T6. 発動予約のうち、残り0になったものを処理
  T7. 「Nターンごと」効果

[プレイヤー操作] カード使用 / ドリンク使用 / スキップ
  P1. 使用条件の判定
  P2. 効果内条件の判定
  P3. コストを払う
  P4. 「コストで体力減少時」トリガー
  P5. 「スキルカード使用時」トリガー
  P6. カード効果を上から1行ずつ処理
  P7. 「スキルカード使用後」トリガー
  P8. 使用数が残っていればプレイヤー操作に戻る

[ターン終了]
  E1. 「ターンスキップ時」トリガー(スキップした場合)
  E2. 「ターン終了時」効果
  E3. 好印象によるパラメータ上昇
  E4. 手札を捨札へ
  E5. ターン制ステータスの残りターンを1減らす(発動予約以外)
  E6. 残りターンがあれば[ターン開始]へ、無ければ終了
```

- 同じタイミングの効果は、育成アイテム(入手順)→ 強化状態・持続効果(付与順)。[確認]
- 参照系の効果は、その行を処理する時点の値を読む。[確認]
- カード自身が付与した持続効果: 「使用時」(P5)は自身に反応しない。「使用後」(P7)は反応する。[確認]

## 11. ターン制ステータスの数え方 [確認]

| 付与したタイミング | そのターン終了時に減るか |
|---|---|
| プレイヤー操作中に初めて付与 | 減らない(付与ターン+Nターン効く) |
| ターン開始〜操作前に初めて付与 | 減る |
| すでに付与済みのものに上乗せ | 通常どおり減る |

- 発動予約はターン開始でカウントする。「次のターン」は1、「2ターン後」は2。
- パラメータ上昇量増加は、%とターン数の組が同じものだけ合算する。

[Uta案] ステータスごとに「初付与フェーズ」を記録し、E5 で減らすか判定する。上昇量増加は `List<(percent, remainingTurns)>` で持つ。

## 12. 強化

| 種類 | 内容 | 持続 |
|---|---|---|
| 強化(+) | カードを強化版に置き換える | プロデュース中ずっと |
| レッスン中強化 | 一時的に強化版として扱う | そのレッスン中 |

- レッスン中強化はカードインスタンスのフラグで持つ。[Uta案]
- 強化済みのカードにレッスン中強化をかけても何も起きない。[決定]

---

## 13. 乱数と再現性 [Uta案]

- 乱数を使う箇所: 山札シャッフル、不調カードの生成位置、ランダム生成系。
- レッスンごとにシードを1つ持ち、決定的な疑似乱数 `xoshiro256**` で生成する（2026-10-27 決定。[repository-layout.md](../architecture/repository-layout.md) 10.3）。`System.Random` は使わない。
- シードと操作列があれば同じ結果を再現できるようにする。サーバー検証・不具合再現・リプレイに使う。

## 15. 実装フェーズ [決定]

仕組みは最初から全ステータス分を用意し、カードとして動かす範囲を段階的に広げる。順番: 好印象 → 元気 → 好調 → 集中 → 育成アイテム・ドリンク。

### 15.1 フェーズ0: 共通基盤(フェーズ1と同時)

- カード定義の読み込み。全プリミティブ・コスト・条件をスキーマ上は定義しておく
- ゾーンと移動、ターン処理順の全ステップ
- 8章の全ステータスの入れ物と、11章の数え方
- 9.2 のパイプライン(未実装の項は「倍率1・加算0」で通す)
- 決定的な乱数、固定小数点の数値型

[Uta案] 未実装のプリミティブを使うカードは、マスタ読み込み時にエラーにする。

### 15.2 フェーズ1: 好印象(理論)

| 区分 | 範囲 |
|---|---|
| ステータス | 好印象、元気(肩代わりのみ)、消費体力減少、消費体力削減、使用数追加 |
| プリミティブ | param、paramByRatio(好印象)、addGenki、addTurns、addStack、draw、addUses、persistent(使用時) |
| コスト | consume、hpDirect |
| カード | F01〜F06、L01、L02、L04、L07、L10、L14、L15 |

### 15.3 フェーズ2: 元気(理論)

| 区分 | 追加する範囲 |
|---|---|
| ステータス | やる気、元気増加無効、消費体力増加 |
| プリミティブ | paramByRatio(元気・やる気)、scaleResource、setResource、addFixedGenki、recoverHp |
| カード | F07、L03、L05、L06、L08、L09、L11、L12、L13 |

### 15.4 フェーズ3: 好調(感性)

| 区分 | 追加する範囲 |
|---|---|
| ステータス | 好調、絶好調 |
| プリミティブ | param の goodScale |
| コスト | goodConditionTurns、excellentTurns |
| カード | S01、S04、S06、S07、S11 |

### 15.5 フェーズ4: 集中(感性)

| 区分 | 追加する範囲 |
|---|---|
| ステータス | 集中 |
| プリミティブ | param の hits、focusScale |
| コスト | focus |
| カード | S02、S03、S05、S08、S09、S10、S12、S13、S14 |

好調×集中の組み合わせで 9.2 の式全体を検証して完了とする。

### 15.6 フェーズ5: 育成アイテム・ドリンク

| 区分 | 範囲 |
|---|---|
| ドリンク | プレイヤー操作中に使う消費アイテム。所持上限3、レッスン・試験中のみ。ターンもスキルカード使用数も消費しない [確認] |
| 育成アイテム | プロデュース中ずっと持つ常駐効果。持続効果と同じトリガーで発動し、「レッスン内N回」の回数制限を持てる |

### 15.7 完了条件 [Uta案]

- そのフェーズの全カードについて、9章の式から出した期待値のユニットテストが通る
- 同じシードと操作列で、クライアントとサーバーの結果が完全に一致する（`Uta.Domain` の単体テストで確かめる。本番のクライアントはシードを持たない。[ADR 0008](../decisions/0008-shared-domain-and-onion.md)）
