# プロデュース（育成）

## 目的

複数ターンの行動（カード使用／休息）でパラメータを伸ばし、最終評価と報酬を得る育成ループの基礎部分を、サーバー権威で実装する。

## 完了条件（基礎部分）

- [ ] 育成開始 → ターン実行 → 最終評価・報酬付与 が サーバー経由で動く
- [ ] ターン進行・計算・乱数はすべてサーバー。クライアントは入力と表示のみ
- [ ] 中断・再開ができる（状態がサーバーに保存されている）
- [ ] 同一シード＋同一操作列で結果が再現できる（テスト・検証用）

## 決まっていること

- サーバー権威（[CLAUDE.md](../../../CLAUDE.md)）
- 通信は MagicOnion の Unary（[ADR 0002](../decisions/0002-magiconion.md)）
- 3Dライブとは接続しない（[ADR 0003](../decisions/0003-defer-3d-live.md)、proposed）

> 以下の「叩き台」は**すべて推測・仮置き**。数値はバランス検証をしておらず、実装前にシミュレーションで調整する前提。決まったものから「決まっていること」へ移す。

## 叩き台 1: 全体ルール

| 項目 | 仮値 | 備考 |
|---|---|---|
| 総ターン数 | 12 | 1育成 = 12ターン。短くして検証しやすくする |
| パラメータ | 3種 | 歌唱 / 律動 / 表現（名称は仮。最終はオリジナル名に） |
| パラメータ上限 | 各 1000 | |
| 体力 | 最大 40、開始時 40 | 0 未満になる行動は選べない |
| デッキ | 10枚 | 所持カードから編成 |
| 手札 | 毎ターン 3枚 | 山札からドロー。山札が尽きたら捨て札をシャッフル |
| 1ターンの行動 | 手札から1枚使用 **または** 休息 | |
| 休息 | 体力 +15（上限まで）、手札はそのまま持ち越し | 仮 |

## 叩き台 2: カード

カードは「コスト（体力）」と「効果」を持つ。

| フィールド | 内容 |
|---|---|
| id / name | マスタ ID / 表示名（オリジナル名） |
| cost | 消費体力（0〜12） |
| gains | 各パラメータの基礎上昇値 |
| effects | 追加効果（任意）: 体力回復、状態付与など |
| rarity | N / R / SR（ガチャ側と共通） |

例（仮）:

| カード | cost | 効果 |
|---|---|---|
| 基礎練習 | 5 | 歌唱 +60 |
| 通し稽古 | 8 | 歌唱 +40 / 律動 +40 |
| 集中の時間 | 4 | 状態「好調」を3ターン付与 |
| 小休止 | 0 | 体力 +8 |
| 渾身の一曲 | 12 | 表現 +150 |

**状態**: 状態は1種類のみで始める（仮）。

- 好調: 3ターンの間、カードによるパラメータ上昇が ×1.5

## 叩き台 3: 計算式

カード使用時のパラメータ上昇:

```
gain[p] = floor( card.gains[p] × character.growth[p] × stateMultiplier )
param[p] = min( param[p] + gain[p], 1000 )
stamina  = stamina - card.cost
```

- `character.growth[p]`: キャラごとの成長率（例: 歌唱 1.2 / 律動 1.0 / 表現 0.9）
- `stateMultiplier`: 好調中 1.5、それ以外 1.0
- 端数は **floor**（サーバー実装は整数演算に寄せ、浮動小数の差異を避ける。推測）

最終評価:

```
score = 歌唱 + 律動 + 表現      // 最大 3000
```

| ランク | score | 報酬（疑似通貨・仮） |
|---|---|---|
| S | 2400〜 | 300 |
| A | 1800〜 | 200 |
| B | 1200〜 | 120 |
| C | 〜1199 | 50 |

概算（未検証）: 1ターン平均で合計 約150 上昇すれば 12ターンで約1800（Aランク）。休息を数回挟む前提でも届くか、シミュレーションで要確認。

## 叩き台 4: 乱数とサーバー状態

- 育成開始時にサーバーが `seed` を生成し、セッションに保存する
- ドローはシードから決定的に行う（同一シード＋同一操作列 → 同一結果）。クライアントは乱数を持たない
- セッション状態（保存対象）: `sessionId`, `userId`, `turn`, `stamina`, `params`, `state`, `deck/draw/discard`, `hand`, `seed`, `rngCursor`, `status`
- ターン実行は `turn` 番号を要求に含め、再送でも二重適用しない。再送の判定はサーバー基盤の冪等性（`x-request-id` + `last_responses`、[server-foundation](../architecture/server-foundation.md)）に任せる想定（推測）
- 1ユーザーにつき進行中のセッションは1つ（仮）

## 未決事項

- 上記の叩き台の数値すべて（ターン数、体力、上昇値、ランク閾値、報酬）
- 状態の種類を増やすか（好調以外）
- カードの追加効果の種類（体力回復・ドロー増加など）
- キャラの育成中固有要素（成長率以外）の有無
- 編成のルール（同名カード枚数制限、レアリティ制限）
- 途中放棄の扱い（報酬なしで破棄／一定期間で自動失効）
- マスタデータの形式（JSON／CSV）と配信方法
- 保存先 DB（基盤の推奨は PostgreSQL + Npgsql + Dapper、未確定。[server-foundation](../architecture/server-foundation.md)）
