# ADR 0007: マスタデータを MasterMemoryAddons でクライアント用・サーバー用に出し分ける

> 注記（2026-10-28）: 「決定」のうち「**バイナリはコミットせず、ビルドのときに作る**」は [ADR 0013](0013-commit-masterdata-binary.md) で置き換えた（バイナリもコミットする）。それ以外の決定は有効。

## 状況

[ADR 0002](0002-magiconion.md) と [CLAUDE.md](../../../CLAUDE.md) は、マスタ型を `shared/` に置いて Unity とサーバーで共有する方針だった。しかしこの方式だと、サーバー専用のテーブル・列（レンタル候補、報酬の設定など）の型がクライアントから見え、配布物にも含まれる。

マスタデータは MasterMemory を使う（[ADR 0004](0004-server-foundation.md)）。MasterMemory は C# のクラスでテーブルを定義できる強みがあるが、列単位でクライアント用・サーバー用に出し分ける仕組みはない。自作のアドオン [MasterMemoryAddons](https://github.com/chinpanGX/MasterMemoryAddons)（`external/MasterMemoryAddons`、[ADR 0005](0005-foundation-submodule.md)）は、定義に付ける `[ClientOnly]` / `[ServerOnly]` で、それぞれの側に要るものだけを残したソースとバイナリを出力する。

## 決定

- マスタ定義の正本は `masterdata/Definitions/`（全列入りの C# クラス）に置く。**Unity にも `shared/` にも入れない**
- アドオンの `code-gen` でクライアント用・サーバー用のソースを生成し、各プロジェクトに置く。**マスタ型は `shared/` に置かない**（ADR 0002・CLAUDE.md のうち「マスタ型を `shared/` に置く」の部分を、この ADR が置き換える。サービスIF・DTO は引き続き `shared/`）
- CSV の検証とバイナリ生成は `master-gen` で行う。クライアント用バイナリは暗号化し、配信は Uta 側（Addressables など）で行う
- **マスタの列の型は `int` / `long` / `string` / `bool` / enum のみ**とする（2026-10-27 に確定）。`float`・配列・nullable は使わない
  - 小数は整数で持つ（万分率・パーセントなど）。複数の値は子テーブルに分けて親の ID と順序で持つ
- **マスタの正本 `masterdata/` をリポジトリの最上位に置く**（2026-10-27 に確定）
- **カード効果などの入れ子は、汎用列＋型付きの参照列で表す**（2026-10-27 に確定）。効果の種類は enum の `Op`、値は `Value`・`Arg1`〜`Arg3`（`int`）、他のテーブルを指す値は `RefCardId` などの専用の列に `[Exists(AllowEmpty = true)]` を付ける。`Op` ごとの引数の意味は一覧にし、`IValidatable` で検証する
- **生成したソースはコミットし、CI の `master-gen --check` で生成し忘れを検出する。バイナリはコミットせず、ビルドのときに作る**（2026-10-27 に確定）
- **配信は、まずアプリに同梱（StreamingAssets）し、あとで Addressables によるダウンロードに移る**（2026-10-27 に確定）
- **CSV は Git の `masterdata/csv/` を正本にする**。スプレッドシートは編集の道具とし、タブ名をテーブル名にそろえて書き出す（2026-10-27 に確定）
- Uta で使いながら、必要な改善はアドオン側に入れる（サブモジュール側を先に push してから Uta のポインタを更新する。ADR 0005）

詳細は [architecture/master/masterdata-pipeline.md](../architecture/master/masterdata-pipeline.md)。

## 理由

- 型の遮断を、参照関係（生成物がそれぞれの側にしか存在しない）で物理的に行える
- 1つの定義から列単位で出し分けられるので、定義が二重にならない
- 整数のみにすることで、クライアント（IL2CPP）とサーバー（.NET 10）で計算結果を一致させやすい（[lesson-card.md](../systems/lesson-card.md) 9.6）。CSV も1行1レコードで読みやすい

## 検討した代替案

- 案A: テーブル単位で分ける（サーバー専用の列は別テーブルに切り出し、型をアセンブリで分ける）。列の出し分けが多くなると、テーブルが増えて結合が必要になる。アドオンを使わずに済む点は利点
- 案B: 基本クラスを共通に置き、サーバー側で継承して列を足す。MasterMemory はテーブルの型ごとにシリアライズとインデックスを生成するため、継承との相性が不明で、クライアントとサーバーでバイナリの配置も変わる
- 効果の表現で、`Op` ごとにテーブルを分ける案: 列の意味が明確で検証も厳密だが、効果の種類だけテーブルが増え、記載順に処理するための結合も重くなる
- スプレッドシートを正本にする案: 差分のレビューとビルドの再現ができないため不採用

## 影響・リスク

- **カード定義など入れ子の構造**（[lesson-card.md](../systems/lesson-card.md) 3章）を、配列なしの子テーブルで表す必要がある。汎用列にしたため、`Arg` の意味が `Op` によって変わり、CSV だけでは読みにくい。`Op` ごとの引数の一覧の保守が要る
- 同梱で配信する間は、マスタを更新するたびにアプリの更新が要る
- アドオンは自作で開発中。Unity での実際の読み込みは**未確認**（アドオンの docs が明記）
- アドオンの導入方法（配布形態）は未決。いまは `external/` のサブモジュールとして使う
- アプリが参照する MasterMemory / MessagePack のバージョンを、アドオンのツールと揃える必要がある。MagicOnion が要求する MessagePack のバージョンとの整合は未確認
- 生成物を各プロジェクトにコミットする運用になる場合、定義の変更ごとに生成のし忘れを CI（`master-gen --check`）で検出する必要がある
- `masterdata/` を最上位に追加したため、CLAUDE.md のリポジトリ構成と「`shared/` はサービスIF・DTO・マスタ型」の記述を更新した（2026-10-27）。[ADR 0002](0002-magiconion.md) のうち「マスタ型は `shared/` に置く」の部分は、この ADR で置き換える（ADR 0002 のそれ以外は有効）

## 見直す条件

- アドオンの制約（型の種類、`[Exists]` が別の側のテーブルを参照した場合など）で、Uta のマスタを表せないと分かったとき
- Unity での読み込み（Windows / Android / iOS 実機）で問題が解決できないとき
- 列の出し分けがほとんど不要だと分かったとき（案A で足りる）
