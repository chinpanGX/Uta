# ADR 0004: サーバーは .NET 10 と C# サーバー基盤（MagicOnion + PostgreSQL）を採用

## 状況

サーバーの実行基盤と、認証・冪等性・トランザクション・エラー形式・ログといった共通部分をどう用意するかを決める必要がある。共通部分を毎回作ると、技術先行の目的（育成・ガチャの縦切り）から外れる。

## 決定

- サーバーは **.NET 10**（ASP.NET Core）で作る
- 共通部分は既存の C# サーバー基盤を使う。概要は [architecture/server-foundation.md](../architecture/server-foundation.md)（原典: 基盤の設計書）
- 確定するもの: MasterMemory、MagicOnion、MessagePack
- DB は PostgreSQL + Npgsql + Dapper を第一候補とするが、**最終決定は別途**（未確定）

## 理由

- 認証・冪等性・トランザクション・エラー形式が既に設計されており、育成・ガチャの実装に集中できる
- Unity と共有する `Abstractions` が分離されていて、サーバー専用の依存が Unity に入らない
- サーバー権威の方針（[CLAUDE.md](../../../CLAUDE.md)）と、冪等な再送・同一トランザクションでの更新が噛み合う

## 検討した代替案

- 案A: 基盤を使わず Uta 内で一から作る。工数が大きく、技術先行の目的から外れるため不採用

## 影響・リスク

- `server/` は C# 14 の書き方を許す。`client/` と `shared/` は Unity のため C# 9 の範囲のまま（`.editorconfig` で分離済み）
- 基盤の取り込み方（ソースのコピー／パッケージ参照など）が未確定
- 基盤の設計書は MagicOnion の使う版での API 確認が済んでいない。実装前に確認する（[ADR 0002](0002-magiconion.md) と同じく、公式情報を確認する）
- 基盤側の互換性のない変更が続いているため、分岐元のタグを固定する必要がある

## 見直す条件

- 基盤の API 確認で、前提とした機能（サーバーフィルター、トレーラーの伝搬など）が使えないと分かったとき
- 取り込み方や DB の決定で、構成が大きく変わるとき
