# ADR 0018: 変更の記録は log.md をやめ、git log から取る

[ADR 0017](0017-spec-design-plan-stages.md) の手順のうち「`log.md` に追記する」を置き換える（ADR 0017 のほかの決定は変えない）。

## 状況

wiki の変更のたびに `uta_docs/wiki/log.md` に 1 行足していた。同じ内容をコミットメッセージにも書くので二重になり、1 行が長くなって読みにくい。ブランチをまたぐと先頭の行がぶつかりやすい。

## 決定

- `log.md` に追記するのをやめる。これまでの履歴は `uta_docs/raw/2026-11-01-wiki-log.md` に移し、変更しない一次資料として残す
- 変更の記録はコミットメッセージに書く。1 行目に何を変えたか、本文に決めたこと・その理由（ユーザーの判断かどうか）を書く
- 履歴は `git log` から引く。例: wiki 全体は `git log -- uta_docs/wiki`、1 ページは `git log --follow -- <パス>`

## 理由

- コミットメッセージと log.md の二重の記録をなくせる。git log なら、どのファイルがどう変わったかも一緒に見られる
- ブランチをまたいだときに log.md がぶつからない

## 検討した代替案

- log.md を残し、1 行を短くする: 二重の記録は残る
- log.md を自動生成する: 生成の手順を増やすほどの必要がない

## 影響・リスク

- コミットメッセージが記録になるので、1 行目と本文を省かずに書く。マージコミットだけでは中身が分からないので、PR のブランチのコミットにも書く
- wiki の外（Obsidian だけ）では履歴が見えない

## 見直す条件

- git log では探しにくい、とユーザーが判断したとき
