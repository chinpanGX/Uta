# レッスン・試験のカードロジック

[プロデュース](produce.md)のレッスン・試験で使うスキルカードの挙動を、実装できる粒度で定義する。

参考作品のシステム構造を調査して決めた。名称は Uta の仮称で、カードは記号(F01 など)で表す([ADR 0001](../decisions/0001-ip-policy.md))。表示名は未決。

## 凡例

- **[確認]** 参考作品の攻略情報で裏取りした構造
- **[決定]** Uta で決めたこと
- **[Uta案]** 実装方針の提案(まだ決定ではない)

数値: カード効果の数値は、参考作品の値を**そのまま**使う([ADR 0015](../decisions/0015-reference-card-values.md))。

## 1. スコープ

| 含める | 含めない |
|---|---|
| プラン: 感性 / 理論 / 共通 | 第3のプラン(指針を切り替える型)一式 |
| レアリティ: N / R / SR / SSR | 最上位レアのカード |
| アクティブ / メンタル / 不調カード(1種のみ) | カードのカスタマイズ |
| 強化(+)、レッスン中強化 | 再演、使用準備 |
| 発動予約、持続効果 | レッスンのギミック(応援・トラブル) |
| | 山札操作系の特殊効果 |

実装範囲の決定 [決定]:

| 項目 | 方針 |
|---|---|
| 第3のプラン | 実装しない |
| 育成アイテム・ドリンク | 実装する(フェーズ5)。カードと同じ効果エンジン(7章、10章)に乗せる |
| 低下状態(デバフ) | 採用したカード・アイテムが使うものだけ実装する |
| レッスンのギミック | 実装しない |
| 特殊な効果(7.6) | その効果を持つカードを採用するときに実装する |
| カードの枚数 | 各フェーズ10〜20枚程度で動作確認。全カードを揃えるかはフェーズ4の完了時に判断する [仮] |

## 2. 用語

| 用語 | 意味 |
|---|---|
| 山札 / 手札 / 捨札 / 除外 | カードの置き場(4章) |
| 消費 | 元気→体力の順に払うコスト。補正の影響を受ける |
| 体力消費 | 元気を無視して体力から直接払うコスト。補正の影響を受けない |
| 使用条件 | 満たさないとカードを使えない条件 |
| 効果内条件 | 効果の一部だけを条件付きで発動する条件 |
| 発動予約 | 「次のターン、〜」「Nターン後、〜」形式の遅延効果 |
| 持続効果 | 「以降、〜」「以降のNターンの間、〜」形式の常駐トリガー |
| 審査ターン | 試験で、そのターンに加点対象となるパラメータ |

ステータス名(好調・集中・好印象・やる気・元気など)は仮称。公開前に Uta 独自の名称に置き換える([glossary](../glossary.md))。

## 3. カード定義(マスタデータ)

### 3.1 フィールド

| フィールド | 型 | 内容 |
|---|---|---|
| id | int | 一意ID。マスタの ID は `int`([repository-layout.md](../architecture/repository-layout.md) 10.1)。F01 などの記号は仕様上の呼び名 |
| name | string | 表示名(未決) |
| plan | enum | sense(感性) / logic(理論) / free(共通) |
| type | enum | active / mental / trouble |
| rarity | enum | N / R / SR / SSR |
| unlockLv | int | 出現に必要なプレイヤーLv |
| onceInLesson | bool | レッスン中1回。使うと除外へ |
| unique | bool | 重複不可。デッキに同じカードを2枚持てない |
| startInHand | bool | レッスン開始時に手札に入る |
| base | CardFace | 通常版の性能 |
| enhanced | CardFace | 強化版(+)の性能 |

`CardFace` の中身:

| フィールド | 内容 |
|---|---|
| costs | コストの配列(5章)。複数持てる |
| useConditions | 使用条件の配列(6章)。すべて満たすと使用可 |
| effects | 効果の配列(7章)。**記載順に上から処理** [確認] |

強化で変わるのは数値だけでなく、コスト種別・効果の追加・条件の変化もある。そのため通常版と強化版は差分ではなく丸ごと別定義で持つ。[Uta案]

### 3.2 表現例(YAML)

```yaml
- id: 101   # S10(値は例。採番の規則は作らない)
  plan: sense
  type: active
  rarity: R
  unlockLv: 13
  onceInLesson: true
  base:
    costs: [{ kind: consume, value: 4 }]
    effects:
      - { op: GainParam, value: 17, focusScale: 1.5 }
  enhanced:
    costs: [{ kind: consume, value: 4 }]
    effects:
      - { op: GainParam, value: 23, focusScale: 2.0 }

- id: 102   # L13(値は例)
  plan: logic
  type: active
  rarity: SR
  unlockLv: 1
  onceInLesson: true
  base:
    costs: [{ kind: hpDirect, value: 3 }]
    effects:
      - { op: GainParamByGenki, value: 130 }  # 減少前の元気を参照
      - { op: ScaleGenki, value: 50 }  # 元気を半分に
  enhanced:
    costs: [{ kind: hpDirect, value: 3 }]
    effects:
      - { op: GainParamByGenki, value: 180 }
      - { op: ScaleGenki, value: 50 }
```

L13 のように「参照してから変化させる」カードは、効果の記載順がそのまま意味になる。

## 4. ゾーンと移動

| ゾーン | 内容 |
|---|---|
| 山札 | レッスン開始時にデッキ全体をシャッフルして置く |
| 手札 | ターン開始時に山札から3枚引く [確認] |
| 捨札 | 使用済みカード、ターン終了時に残った手札 |
| 除外 | レッスン中1回のカードの使用後。レッスン中は戻らない [確認] |

移動ルール:

- 通常カードは使用後に捨札へ、レッスン中1回のカードは除外へ。[確認]
- ターン終了時、使わなかった手札は捨札へ。[確認]
- 山札が0枚になった瞬間に、捨札をすべてシャッフルして新しい山札にする。[確認]
  - ターン開始時のドローでも、効果によるドローでも同じ。
  - 山札を0枚にしたドローで手札に来たカードは、この再シャッフルに含まれない。
  - 1回のドローの途中で0枚になった場合は、再シャッフル後の山札から残りを引く。[決定]
  - 山札も捨札も空なら、引ける分だけ引く。[決定]
  - 山札が 0 枚のままドローするとき(山札も捨札も空になった後に捨札ができた場合など)に捨札があれば、その時点で捨札をシャッフルして山札にしてから引く。[決定。2026-10-31]
  - 手札が空、または使えるカードが無い場合は、スキップしかできない。[確認]
- 「レッスン開始時手札に入る」カードは、1ターン目に優先して手札に入れる。[決定]
  - 3枚未満なら、残りを山札から引いて3枚にする
  - 3枚以上なら、すべて入れる。ただし5枚まで
  - 上限を超えた分は山札にシャッフルして混ぜる

### 4.1 レッスンルールのマスタ [決定]

| 項目 | 値 |
|---|---|
| 毎ターンのドロー枚数 | 3 |
| 1ターン目の最低手札枚数 | 3 |
| 1ターン目の開始時手札カードの上限 | 5 |
| 1ターンの基本スキルカード使用数 | 1 |
| スキップ時の体力回復 | 2 |

### 4.2 レッスン・試験の開始と終了 [確認]

- 体力はプロデュース全体で持ち越す。元気と強化状態はレッスンごとにリセットする。
- 終了条件:
  - レッスン: 規定ターン数の経過、またはパーフェクト目標への到達
  - 試験: 規定ターン数の経過。初級・中級の中間試験のみ、規定スコアへの到達でも終了([produce.md](produce.md) 5.1)
- ターン数・目標値は [produce.md](produce.md) のマスタから渡す。
- パーフェクト目標を超えた分は切り捨て、パーフェクト目標の値で止める。[決定]

## 5. コスト

| kind | 表記例 | 払い方 | 補正の影響 |
|---|---|---|---|
| consume | 消費4 | 元気から先に払い、足りない分を体力から | 受ける(9.1) |
| hpDirect | 体力消費3 | 元気を無視して体力から直接 | 受けない |
| goodConditionTurns | 好調消費2ターン | 好調のターン数を減らす | なし |
| focus | 集中消費3 | 集中を減らす | なし |
| impression | 好印象消費2 | 好印象を減らす | なし |
| motivation | やる気消費3 | やる気を減らす | なし |
| excellentTurns | 絶好調消費1 | 絶好調のターン数を減らす | なし |

- 体力消費は、消費体力の追加・削減・増加・減少もすべて無視する。[確認]
- 使えるかどうかの判定 [確認]:
  - consume: 元気+体力 ≥ 最終消費量(9.1)
  - hpDirect: 体力 ≥ コスト
  - ステータスを払うコスト: その値(ターン数) ≥ コスト
  - コスト0のカードは体力0でも使える。[決定]
- コストは使用条件とは別扱い。[確認]

## 6. 条件

### 6.1 条件の種類

| 条件 | 例 |
|---|---|
| 好調状態である / 好調がNターン以上 | S11 / S04 |
| 絶好調状態である | |
| 集中がN以上 | S05 |
| 好印象がN以上 | L02 |
| やる気がN以上 | |
| 元気がN以上 / 元気が0 | |
| 体力がN%以上 | F05 |
| Nターン目以降 | |
| レッスンのクリア目標のN%以下 | |

条件は `{ subject, comparator, value }` の汎用形で表す。複数の条件はグループにまとめ、すべて満たすと真(AND)。使用条件と効果内条件で同じ形を使う。[決定。2026-10-28。マスタでの表し方は [masterdata-pipeline.md](../architecture/masterdata-pipeline.md) 3章・3.1]

### 6.2 判定タイミング [確認]

- 効果内条件の判定は、コストを払う**前**に行う。
- 同じタイミングで発動する複数の効果は、条件判定をまとめて先に済ませ、その後に効果を処理する。

## 7. 効果プリミティブ [決定。2026-10-28]

下の op をマスタと共有ドメインの `EffectOp` enum にする。op の名前・数値、op ごとの列(`Status` / `Trigger` / `Value` / `Arg1`〜`Arg3` / 参照列)の対応と、ステータス・トリガー・コスト・条件の enum は [lesson-enums.md](../architecture/lesson-enums.md) が正 [決定。2026-10-31]。この章の表は効果の意味だけを書く。効果はグループにまとめ、持続効果・発動予約は中身の効果のグループを指す。どの効果にも効果内条件(条件のグループ)を付けられる。

### 7.1 パラメータ系

| op | 効果文の例 | パラメータ |
|---|---|---|
| GainParam | パラメータ+17 / パラメータ+4(2回) | value, hits(既定1), focusScale(既定1), goodScale(既定1) |
| GainParamByImpression / GainParamByGenki / GainParamByMotivation | 好印象の150%分パラメータ上昇 | percent(参照元は op で分ける) |
| AddParamBonus | パラメータ上昇量増加30%(1ターン) | percent, turns |

- `hits` は連撃。集中は1回ごとに加算される。[確認]
- `focusScale` は「集中効果をN倍適用」、`goodScale` は「好調効果をN倍適用」。[確認]
- マスタに移すときは、小数を整数（パーセント）にする（`focusScale: 1.5` → `150`）。効果は `Op`・`Status`・`Trigger`・`Value`・`Arg1`〜`Arg3` と参照列で表す（[masterdata-pipeline.md](../architecture/masterdata-pipeline.md) 3章、[lesson-enums.md](../architecture/lesson-enums.md)、[ADR 0007](../decisions/0007-masterdata-with-addons.md)）。`hits`・`focusScale`・`goodScale` の既定値は、マスタでは 0（空欄）で表す

### 7.2 リソース系

| op | 効果文の例 |
|---|---|
| AddGenki | 元気+4(やる気の影響を受ける) |
| AddFixedGenki | 固定元気+2(強化・低下状態の影響を受けない) |
| RecoverHp | 体力回復3 |
| ScaleGenki | 元気を半分にする。端数は切り捨て [決定] |
| SetGenki | 元気を0にする |

### 7.3 ステータス付与系

| op | 効果文の例 |
|---|---|
| AddStatus | 好調2ターン / 絶好調3ターン / 消費体力減少2ターン / 元気増加無効2ターン / 集中+2 / 好印象+3 / やる気+2 / 消費体力削減1 / 低下状態無効1回 |
| AddStatusPercent | 好印象強化+10% / 集中強化20%(3ターン) |

### 7.4 カード操作系

| op | 効果文の例 |
|---|---|
| DrawCards | スキルカードを引く / 2枚引く |
| AddCardUses | スキルカード使用数追加+1 |
| ReplaceHand | 手札をすべて入れ替える |
| EnhanceHand | 手札をすべてレッスン中強化 |
| CreateCard | 不調カードを山札のランダムな位置に生成 |

### 7.5 時間差・常駐系

| op | 効果文の例 |
|---|---|
| ScheduleEffect | 次のターン、パラメータ+32 / 2ターン後、スキルカードを引く |
| AddPersistent | 以降、アクティブスキルカード使用時、集中+1 / 以降の3ターンの間、ターン開始時、パラメータ+5 |

`ScheduleEffect` は `{ delayTurns, effects[] }`、`AddPersistent` は `{ trigger, condition?, effects[], duration? }`。`duration` はターン制限と回数制限の2種。

`AddPersistent` の `condition` は、ほかの op と同じ**効果内条件**で、持続効果を**付与するかどうか**の条件 [決定。2026-10-31]。発動のたびに見る条件は、発動する効果(`effects[]`)の側の効果内条件に付ける。例は [lesson-enums.md](../architecture/lesson-enums.md) 6章。

### 7.6 後回しにするプリミティブ(そのカードを採用するときに実装)

| op | 内容 | 理由 |
|---|---|---|
| RepeatNext | 次に使うカードの効果をもう1回発動 | 再発動時にトリガーを再誘発しない等の細則が多い |
| AddLessonTurn | レッスン・試験のターンを1追加 | 試験の審査ターン決定ルールと絡む |
| DeckManipulate | 特定のカードを山札の一番上へ | 使用頻度が低い |

## 8. ステータス

| ステータス | 単位 | 効果 | 減り方 |
|---|---|---|---|
| 好調 | ターン | パラメータ上昇量+50% | ターン経過で1減 |
| 絶好調 | ターン | 好調の倍率に「好調ターン数×10%」を加算。好調が0なら効果なし | ターン経過で1減 |
| 集中 | 値 | パラメータ上昇量+集中値 | 減らない(コストで消費) |
| 集中強化 | % | 集中の効果を(1+N%)倍 | 付与時の指定 |
| 好印象 | 値 | ターン終了時、好印象と同じだけパラメータ上昇 | ターン開始時に1減 |
| 好印象強化 | % | 好印象による上昇を増加 | 付与時の指定 |
| やる気 | 値 | 元気の増加量+やる気値 | 減らない(コストで消費) |
| 元気 | 値 | consume コストを体力より先に肩代わり | 消費で減る |
| 消費体力減少 | ターン | consume の消費量を50%に | ターン経過で1減 |
| 消費体力増加 | ターン | consume の消費量を2倍に | ターン経過で1減 |
| 消費体力削減 | 値 | consume の消費量からN引く | 減らない |
| 元気増加無効 | ターン | 元気が増えない | ターン経過で1減 |
| 低下状態無効 | 回数 | 低下状態の付与を1回打ち消す | 打ち消すたび1減 |
| パラメータ上昇量増加 | %・ターン | パラメータ上昇量を(1+N%)倍 | ターン経過 |
| スキルカード使用数追加 | 回数 | このターンにもう1枚使える | ターン終了で消える |

**低下状態** [決定。2026-10-31]: 消費体力増加と元気増加無効を「低下状態」とする。低下状態無効は、この 2 つの付与を 1 回打ち消す。ほかの低下状態(消費体力の追加、パラメータ上昇量の減少など)は、使うカード・アイテムを採用するときに、8章の表と 9章の式に項を足す(7.6 と同じ扱い)。

値の範囲 [決定]:

- 元気・好印象・やる気・集中・ターン数は0未満にならない。
- 体力は0〜最大体力。体力回復は最大体力で止まる。
- 最終消費量(9.1)は0未満にならない。

## 9. 計算式

### 9.1 最終体力消費量(consume) [確認]

```
最終消費量 = ceil( カードの消費量 × 消費倍率 − 消費体力削減 )

消費倍率:
  減少あり・増加なし → 0.5
  減少なし・増加あり → 2
  両方あり / 両方なし → 1
```

### 9.2 パラメータ上昇値 [確認]

```
カード値 = スキルカードのパラメータ + 集中 × (1 + 集中強化) × focusScale

好調倍率:
  好調なし              → 1
  好調あり・絶好調なし  → 1 + 0.5 × goodScale
  好調あり・絶好調あり  → 1 + (0.5 + 0.1 × 好調ターン数) × goodScale

最終パラメータ上昇値 = ceil( カード値 × 好調倍率 × (1 + 上昇量増加の総和) )
```

- 低下状態の項(消費体力の追加、上昇量の減少)は、採用するまで式に入れない(8章)。
- 連撃は1回ごとに計算して加算する。
- `GainParamBy*` の「スキルカードのパラメータ」は `ceil(参照値 × 倍率)`。
- 丸めは式の最後に1回だけ行う。
- 集中強化の式は仮実装。フェーズ4以降に検証する。[決定(仮)] 初期カードセットには集中強化を持つカードを入れない。

### 9.3 元気の増加量

```
元気増加量 = 効果の値 + やる気
```

- 元気増加無効中は増えない。固定元気も増えない。[決定]
- 固定元気はやる気の影響を受けない。[確認]

### 9.4 好印象によるパラメータ上昇

```
上昇値 = ceil( 好印象 × (1 + 好印象強化) × (1 + 上昇量増加の総和) )
```

- 好調倍率は乗せない。[決定]

### 9.5 試験スコア

```
スコア上昇値 = ceil( 最終パラメータ上昇値 × 最終スコアボーナス / 100 )
```

- 切り上げは2段階(パラメータ上昇値で1回、スコアで1回)。[確認]
- 最終スコアボーナス(信頼度補正を含む)の式は [produce.md](produce.md) 5.2(Uta独自)。[決定]
- 試験の細部 [決定。2026-10-31]:
  - 試験はクリア目標・パーフェクト目標を持たない。条件の「クリア目標の N%」(`ClearTargetPercent`)は試験では常に偽
  - 中間試験の早期終了: スコアが早期終了スコアに届いたら、そのターンの処理を終えてから試験を終える。届いた後の分も含めてスコアは止めない(超えた分を残す)
  - 審査ターンの列(各ターンのパラメータ)は、試験の開始時に [produce.md](produce.md) 5.1・10.3 で決めて、レッスンの設定として渡す

### 9.6 数値型 [決定]

- `float` / `double` / `decimal` を使わない。整数(パーセント・千分率・万分率の整数)で持ち、計算の途中は `long` の分子と分母で持って最後に 1 回だけ丸める([lesson-domain-types.md](../architecture/lesson-domain-types.md))。
- 理由: クライアントの予測の表示とサーバーの確定値を一致させやすくするため。また、同じシード・操作列で結果を再生するテスト([produce.md](produce.md) 10.6)を成り立たせるため。クライアント(IL2CPP)とサーバー(.NET 10)で浮動小数点の結果がずれる心配もなくなる。

## 10. ターン処理順 [確認]

```
[レッスン開始]
  L1. 「レッスン開始時」効果の条件判定 → 処理
  L2. 山札をシャッフル、開始時手札カードを配置

[ターン開始]
  T1. 発動予約の残りターンを1減らす
  T2. 好印象を1減らす(ターン開始時の他の効果より前)
  T3. 「ターン開始時」効果
  T4. 山札から3枚引く(1ターン目は4章のルール)
  T5. 「ターン開始後」効果
  T6. 発動予約のうち、残り0になったものを処理
  T7. 「Nターンごと」効果

[プレイヤー操作] カード使用 / ドリンク使用 / スキップ
  P1. 使用条件の判定
  P2. 効果内条件の判定
  P3. コストを払う
  P4. 「コストで体力減少時」トリガー
  P5. 「スキルカード使用時」トリガー
  P6. カード効果を上から1行ずつ処理
  P7. 「スキルカード使用後」トリガー
  P8. 使用数が残っていればプレイヤー操作に戻る

[ターン終了]
  E1. 「ターンスキップ時」トリガー(スキップした場合)
  E2. 「ターン終了時」効果
  E3. 好印象によるパラメータ上昇
  E4. 手札を捨札へ
  E5. ターン制ステータスの残りターンを1減らす(発動予約以外)
  E6. 残りターンがあれば[ターン開始]へ、無ければ終了
```

- 同じタイミングの効果は、サポートアビリティ(編成順)→ 育成アイテム(入手順)→ 強化状態・持続効果(付与順)。[確認](サポートアビリティが先: [idol-support.md](idol-support.md) 2.3)
- 参照系の効果は、その行を処理する時点の値を読む。[確認]
- カード自身が付与した持続効果: 「使用時」(P5)は自身に反応しない。「使用後」(P7)は反応する。[確認]
- L1 の時点では山札・手札・捨札は空。L1 の効果はゾーンを参照・操作しない [決定。2026-10-31]。「レッスン開始時」のトリガーの下に `DrawCards`・`ReplaceHand`・`EnhanceHand`・`CreateCard` を置いたカード・アイテム・アビリティは、読み込み時にエラーにする(`CardDefinitionValidator`)

### 10.1 レッスンの出力 [決定。2026-10-31]

レッスンエンジンは、レッスン・試験が終わったら次を返す。パラメータへの反映、パラメータボーナス、仕上げボーナスの振り分け、クリア報酬、パーフェクトの回復は、エンジンの外(週の進行。[produce.md](produce.md) 4.3)で行う。エンジンはカードバトルだけを扱う。

| 出力 | 内容 |
|---|---|
| 得たパラメータ | レッスンで得た量(パーフェクト目標で止めた後の値)。試験ならスコア |
| 終わったターンの番号 | 最後に処理したターン |
| 終了理由 | ターン切れ / パーフェクト / 早期終了(中間試験) |
| 体力 | 終了時の体力 |

## 13. 乱数と再現性 [決定]

- 乱数を使う箇所: 山札シャッフル、不調カードの生成位置、ランダム生成系。
- 決定的な疑似乱数 `xoshiro256**` を使う（2026-10-27 決定。[repository-layout.md](../architecture/repository-layout.md) 10.3）。`System.Random` は使わない。
- シードはプロデュースのセッションに1つ。レッスンごとに、そこから独立した乱数ストリーム（週番号＋挑戦回数がキー）を作る。引く順番・操作の記録・保存する状態は [produce.md](produce.md) 10章 [決定]。
- シードと操作列があれば同じ結果を再現できるようにする。再生のテスト・不具合の再現・リプレイに使う(クライアントの結果をサーバーが検証するのではない。[ADR 0008](../decisions/0008-shared-domain-and-onion.md))。

## 15. 実装フェーズ [決定]

仕組みは最初から全ステータス分を用意し、カードとして動かす範囲を段階的に広げる。順番: 好印象 → 元気 → 好調 → 集中 → 育成アイテム・ドリンク。

### 15.1 フェーズ0: 共通基盤(フェーズ1と同時)

- カード定義の読み込み。全プリミティブ・コスト・条件をスキーマ上は定義しておく
- ゾーンと移動、ターン処理順の全ステップ
- 8章の全ステータスの入れ物と、11章の数え方
- 9.2 のパイプライン(未実装の項は「倍率1・加算0」で通す)
- 決定的な乱数、固定小数点の数値型

[決定] 未実装のプリミティブを使うカードは、マスタ読み込み時にエラーにする。フェーズを進めるときは、`CardDefinitionValidator` の対応する `Op` の一覧に足す。

**フェーズごとに変えるコード** [決定。2026-10-31]: 仕組み(全コスト・全条件・全ステータスと 11章の数え方、`GainParam` の連撃と倍率)はフェーズ 1 で先に入れた。以降のフェーズで変えるのは次だけ。

| フェーズ | 変えるコード |
|---|---|
| 2 | `EffectExecutor` に `GainParamByGenki`・`GainParamByMotivation`・`ScaleGenki`・`SetGenki`・`AddFixedGenki`・`RecoverHp` を足し、`CardDefinitionValidator` の対応する一覧に足す |
| 3・4 | カード定義とテストを足すだけ |
| 5 | 別の仕様(15.6)を書いてから決める |
| 6 | 試験(15.6.1) |

**テストのカードの置き場** [決定。2026-10-31]: テストのカード定義は `shared/Uta.Domain.Tests/Lesson/` に、フェーズごとに `Phase<N>Cards` を足す。全フェーズのカードをまとめて返す `ICardCatalog` を 1 つ作り、テストはそれを使う。カード ID は 14章の番号から機械的に振る: F は番号そのまま(F01 = 1)、L は 10 + 番号(L01 = 11)、S は 30 + 番号(S01 = 31)。テストだけで使う合成カードは 900 以上。

**カードのない op の確かめ方** [決定。2026-10-31]: 初期カードセットで使われない op・コスト(`AddFixedGenki`・`RecoverHp`・`SetGenki`、消費体力増加の付与、好調・絶好調・集中のコストなど)は、テストだけの合成カード(ID 900 以上)で op ごとに単体テストする。F08(不調カード)と `CreateCard` はどのフェーズにも入れない(後回し)。
