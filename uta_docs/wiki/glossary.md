# 用語集

プロジェクト内の用語はここで定義する。既存作品固有の名称は使わず、Uta 独自の名称を定義すること。

## 全般

| 用語 | 定義 | 備考 |
|---|---|---|
| Uta | 本プロジェクトの名称 | |
| プロデュース | 育成モード。週ごとの行動選択とレッスン・試験でパラメータを伸ばし、最後に評価を受ける | 名称は仮 |
| ガチャ | 排出テーブルに基づくサーバー抽選 | |
| ライブ | 3D演出で楽曲を再生するパート | 保留中（[ADR 0003](decisions/0003-defer-3d-live.md)） |
| マスタデータ | 静的な設定データ（排出テーブル、カード定義、週構成など） | |
| サーバー権威 | 計算・抽選・所持品更新をすべてサーバーが行う方針 | |
| ADR | Architecture Decision Record。技術選定・方針変更の理由を1件1ファイルで残す記録 | `decisions/` に置く |
| MVP | 最小限の動作範囲。ガチャ→編成→プロデュース→報酬を通す | [game-spec](overview/game-spec.md) |
| 縦切り | 各層を貫く最小の動作確認（Vertical Slice） | |
| 参考作品 | システム構造の調査対象にした既存作品 | 名称は docs に書かない（[ADR 0001](decisions/0001-ip-policy.md)） |

## プロデュース（仮称）

| 用語 | 定義 |
|---|---|
| パラメータ | 歌唱 / 律動 / 表現 の3種 |
| 体力 | カードのコストや授業で消費する資源。プロデュース全体で持ち越す |
| 育成アイドル | 育成対象のキャラカード。Uta は 1 キャラ 1 枚（楽曲の軸を持たない） |
| サポートカード | 編成する補助カード（6枚） |
| プラン | 感性（好調・集中）/ 理論（好印象・やる気）/ 共通 |
| おすすめ効果 | 育成アイドルごとの主軸ステータス。初期デッキと提示されるカードが決まる |
| 初級 / 中級 / 上級 | 難易度（13 / 16 / 18週） |
| 育成pt | プロデュース中だけ使うポイント。相談・おでかけで払う |
| ドリンク | レッスン・試験中に使う消費アイテム（所持上限3） |
| 育成アイテム | プロデュース中ずっと効果を持つアイテム |
| 授業 / 支給 / おでかけ / 相談 / 休む | 週の行動 |
| 特別レッスン | 確率で発生する、目標が高く上昇量も大きいレッスン |
| 仕上げレッスン | 試験直前の週のレッスン |
| 審査比率 | アイドルごとの3パラメータの比率。試験のターン割り振りとスコアボーナスに使う |
| 信頼度 | アイドルごとの永続レベル。試験のスコアボーナスなどが増える（MVP では作らない） |
| プレイヤーLv | アカウント単位のレベル。カードや機能が解放される |
| 不調カード | 授業などのコストとしてデッキに入る、効果のないカード |
| 挑戦回数 | 同じレッスン・試験に挑んだ回数。0 始まりで、試験の再挑戦のたびに 1 増える（[produce](systems/produce.md) 10.2） |
| 局面 | プロデュースの入力待ちの種類（週の選択、カードの選択肢、レッスン、試験の結果など。produce 10.5） |
| クリア目標 / パーフェクト目標 | レッスンで、超えると報酬が出る値 / 届くとレッスンが終わる値（produce 4.1） |
| 仕上げボーナス | 仕上げレッスンでクリア目標を超えた分。3 等分して全パラメータに足す（produce 4.2） |
| スコアボーナス | 試験で、パラメータの上昇をスコアに換算する倍率（produce 5.2） |
| 基準スコア（R） | 試験の NPC のスコアを決める基準の値（produce 5.3） |
| 評価値 / ランク | プロデュースの最終評価の値と、その段階（F〜SS+。produce 6章） |

## レッスン・試験（仮称）

| 用語 | 定義 |
|---|---|
| デッキ / 山札 / 手札 / 捨札 / 除外 | カードの置き場（[lesson-card](systems/lesson-card.md) 4章） |
| 元気 | 消費コストを体力より先に肩代わりする値 |
| 好調 / 絶好調 / 集中 / 好印象 / やる気 | ステータス（[lesson-card](systems/lesson-card.md) 8章） |
| レッスン中強化 | そのレッスンの間だけカードを強化版として扱うこと |
| アクティブ / メンタル | スキルカードの種別。主にパラメータを上げるのがアクティブ、ステータスを付けるのがメンタル |
| 消費 / 体力消費 | コストの種類。消費（consume）は元気 → 体力の順に払い補正を受ける。体力消費は体力から直接払い補正を受けない（[lesson-card](systems/lesson-card.md) 5章） |
| 使用条件 / 効果内条件 | 満たさないとカードを使えない条件 / 満たさないとその効果の行だけ飛ばす条件。効果の一部だけを条件付きで発動するのに使う（[lesson-card](systems/lesson-card.md) 6章） |
| 発動予約 | 「次のターン、〜」「Nターン後、〜」の形の、後で効果を発動させる効果（[lesson-card](systems/lesson-card.md) 7.5） |
| 持続効果 | 「以降、〜」「以降のNターンの間、〜」の形の、付与した後に決まったタイミングのたびに発動する効果。ターン数・回数の制限を持てる（同 7.5） |
| 集中強化 / 好印象強化 | 集中・好印象の効果を % で増やすステータス（同 8章） |
| パラメータ上昇量増加 | パラメータの上昇量を % で増やす、ターン数のあるステータス（同 8章） |
| スキルカード使用数追加 | そのターンにもう 1 枚カードを使えるようにする効果（同 8章） |
| 低下状態 | 消費体力増加と元気増加無効。低下状態無効で打ち消せる（同 8章） |
| 審査ターン | 試験の各ターンに割り振られる、スコアの対象のパラメータ（[produce](systems/produce.md) 5.1） |

## 育成アイドル・ガチャ（仮称）

| 用語 | 定義 |
|---|---|
| トレーニング | 素材とゴールドで行う6段階の強化 |
| 覚醒 | かけらで行う4段階の強化 |
| かけら | ガチャの重複などで得る、アイドルごとの強化素材 |
| 交換メダル | 余ったかけら・交換pt から変換する交換用の通貨（MVP では作らない） |
| ガチャ通貨 | ガチャに使う無償通貨（課金なし） |
| 交換pt | ガチャ1回で1pt。ガチャごとに数え、200pt（マスタで変えられる）で交換対象のカードと交換する（天井。[gacha](systems/gacha.md) 4章） |
| 10連 / 確定枠 | 10 回まとめて引くガチャ。10 枠目が確定枠で、SR 以上だけのテーブルから引く（[gacha](systems/gacha.md) 3.1） |
| 上限解放 / 完凸 | 同じサポートカードを素材にして、レベルの上限を上げること。4 回済んだ状態が完凸（[idol-support](systems/idol-support.md) 2.2） |
| ゴールド | 汎用のゲーム内通貨。トレーニングとサポートカードのレベル上げに使う |
| サポート強化pt | サポートカードのレベル上げに使う素材（ゴールドと一緒に使う）。完凸後の重複からも得る |
| 育成素材 | トレーニングに使う素材（MVP では作らない） |
| パラメータボーナス | レッスンで上がったパラメータに、千分率で上乗せする育成アイドル・サポートカードの性能（[idol-support](systems/idol-support.md) 1.2） |
| アビリティ / サポートアビリティ | 育成アイドル / サポートカードが持つ、決まったタイミングで発動する効果（idol-support 1.7・2.3） |
| 固有スキルカード / 固有育成アイテム | 育成アイドルごとに、プロデュース開始時から持っているカード / アイテム（idol-support 1.2） |
| サポートイベント | 週の行動の前後に確率で起き、パラメータ上昇などが得られるサポートカードのイベント（idol-support 2.4。MVP では作らない） |
| スキルカードサポート | レッスン中に確率で手札のカードをレッスン中強化する、サポートカードの効果（idol-support 2.5。MVP では作らない） |
| アシスト | サポートカードのタイプの 1 つ。体力回復や相談の割引など特殊な能力を持つ |
| レンタル枠 | サーバーのマスタから借りるサポートカードの 6 枚目の枠（idol-support 2.6。MVP では作らない） |
| 所持ID | 所持しているサポートカード1枚ごとに振る ULID。同じカードでも引くたびに別の所持IDになる（[idol-support](systems/idol-support.md) 2.2.1） |

## 技術・設計

| 用語 | 定義 | 備考 |
|---|---|---|
| 共有ドメイン（`Uta.Domain`） | クライアントとサーバーで共有する純粋なゲームルール（計算式、状態遷移、判定） | [repository-layout](architecture/repository-layout.md) 6章 |
| 通信契約（`Uta.Shared`） | サービスIF・DTO・エラーコード | [api-design](architecture/api-design.md) |
| オニオンアーキテクチャ | 依存を常に内側（Domain）へ向ける層の構成 | [ADR 0008](decisions/0008-shared-domain-and-onion.md) |
| ポート | `Application` が定義し、`Infrastructure` が実装するインターフェース | |
| Composition Root | すべての層を組み立てる場所。クライアントでは `Bootstrap` | |
| 予測の表示 | クライアントが共有ドメインで出す、確定前の値（使用可否・スコアの見込みなど）。確定はサーバー | シードは使わない |
| 機能ID | 仕様の機能に付ける ID（`PRD-xx` / `GAC-xx` / `IDL-xx` / `SUP-xx`）。設計書4編の横断に使う | |
| `[ClientOnly]` / `[ServerOnly]` | マスタ定義に付け、クライアント用・サーバー用のどちらの出力に残すかを決める属性 | MasterMemoryAddons |
| 正本 | 他のものを生成する元になる、手で編集するデータ（マスタの定義・CSV） | `masterdata/` |
| スキーマの ID / スキーマのハッシュ | マスタ定義から作る識別子。ハッシュは暗号化の鍵を兼ねるので外に出さず、外にはスキーマの ID を使う | [masterdata-pipeline](architecture/masterdata-pipeline.md) 6章 |
| `Op`（`EffectOp`） | マスタと共有ドメインの効果の種類を表す enum（operation の略）。効果エンジンはこれで処理を切り替える。名前・数値・列の対応は lesson-enums が正 | [lesson-enums](architecture/lesson-enums.md) |
| 効果グループ / 条件グループ | 記載順に処理する効果の並び、すべて満たすと真になる条件の並びを、1つの ID でまとめたもの。カード・持続効果・育成アイテムなどから ID で指す | [masterdata-pipeline](architecture/masterdata-pipeline.md) 3章 |
| 中断 / 放棄 / 破棄 | プロデュースの止め方。中断はアプリの終了で、いつでも再開できる。放棄はプレイヤーの明示の操作。破棄はアプリのバージョン（または状態の形式）が開始時と違うときにサーバーが行う。放棄・破棄は報酬なし | [api-design](architecture/api-design.md) 5章 |
| 同期（`SyncAsync`） | 起動時に1回呼ぶ、副作用のある RPC。プレイヤーの作成と初期付与（初回だけ）、バージョン違いのプロデュースの破棄をまとめて行う | [api-design](architecture/api-design.md) 1章 |
| ULID | 時刻順に並ぶ一意な ID。サーバーが発行する ID に使う（マスタの ID は `int`） | [repository-layout](architecture/repository-layout.md) 10.1 |
| 日付の更新 | 日ごとの区切り。12:00 JST | 同 10.2 |
| Testcontainers | テストのときに Docker でコンテナ（PostgreSQL など）を立ち上げるライブラリ。サーバーの結合テストに使う | [repository-layout](architecture/repository-layout.md) 10.4 |
| dev 環境 | Google Cloud にデプロイした確認用の環境（Cloud Run + Cloud SQL）。本番環境は分けない | [repository-layout](architecture/repository-layout.md) 11章 |
| マスタの日時 | `string` の `yyyy-MM-dd HH:mm:ss`（JST） | 同 10.2 |
| `xoshiro256**` | 共有ドメインで使う決定的な疑似乱数（64 ビット。xorshift の後継） | 同 10.3 |
| 万分率 / 千分率 / パーセント表記 | 小数を整数で持つための単位。確率は万分率、カードの効果の倍率はパーセント、0.1% 刻みが要る値（評価・スコアボーナスの係数、パラメータボーナス）は千分率（2026-10-31） | マスタは小数を扱わない |
| マスターシード | プロデュースのセッションに1つ持つ乱数のシード。ここから用途・場面ごとのストリームを作る | [produce](systems/produce.md) 10.2 |
| 乱数ストリーム | 用途（週構成・週・カードの選択肢・レッスン）と場面（週番号・挑戦回数）ごとに独立した乱数の列 | 同 10.2 |
| 入力待ち | プレイヤーの操作を待つ地点。サーバーは入力待ちから次の入力待ちまでを1回で処理して保存する | 同 10.1 |
| 操作番号 | セッションの操作の記録に付ける 0 からの連番。要求に「次の操作番号」を入れ、古い要求を拒否する | 同 10.4 |
| カードのインスタンス ID | セッションの中だけで使うカードの連番（`int`）。同じカードの2枚を区別する | 同 10.4 |

## 置き換え対象の仮称（ADR 0001）

次の仮称は、参考作品の語と同じか、ほぼ同じ（推測を含む）。**公開・共有の前に必ず Uta 独自の名称へ置き換える**。それまでは仕様の読みやすさを優先して、このまま使う（2026-10-28 決定）。コード上の識別子は、置き換えに備えて英語の独自名にする案（推測・コードを書くときに決める）。

| 区分 | 語 |
|---|---|
| ステータス | 好調、絶好調、集中、好印象、やる気、元気、固定元気、消費体力減少、消費体力増加、消費体力削減、元気増加無効、低下状態無効、集中強化、好印象強化、パラメータ上昇量増加、低下状態 |
| カード | スキルカード、レッスン中強化、アクティブ、メンタル、スキルカード使用数追加 |
| 週の行動 | 授業、おでかけ、相談 |
| サポートカード | サポートイベント、スキルカードサポート |
| 育成アイドル | パラメータボーナス |
| 範囲外の要素の呼び名 | メモリー（produce.md PRD-15）、再演、使用準備（lesson-card.md 1章） |
